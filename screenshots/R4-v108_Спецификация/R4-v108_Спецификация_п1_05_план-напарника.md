# План: контроль вместимости аттракционов

## Цель
Реализовать в конфигурации `amusementpark` учёт вместимости аттракционов:
новый периодический регистр сведений лимитов, регистр накопления загрузки,
контроль лимита при проведении «ПосещениеАттракциона», документ
«ЗавершениеПосещения», права роли «ОператорАттракциона» и тесты YAXUnit.

## Исходное состояние (что уже есть)
- `Документ.ПосещениеАттракциона` — регистратор `АктивныеПосещения` и `ПосещенияАттракционов`,
  проверки билета в `ОбработкаПроведения`.
- `Справочник.ВидыАттракционов`, `Справочник.Аттракционы.ВидАттракциона`.
- `Роль.ОператорАттракциона` (права: Аттракционы, ПосещениеАттракциона, ПродажаБилета),
  элемент `Перечисление.РолиПользователей.ОператорАттракциона` и профиль в
  `ОбщийМодуль.УправлениеДоступомПереопределяемый` — уже существуют, профиль править не нужно.
- Расширение `amusementpark.YAXUNIT` (YAXUnit 25.12). Тест-модуль = общий серверный модуль
  расширения с экспортной `ИсполняемыеСценарии()`.

## Решения по спорным моментам
- **«Лимит задан»** = в срезе последних есть запись и `МаксимумПосетителей > 0`.
  Иначе ограничение не применяется (треб. 5), но загрузка всё равно учитывается.
- **Текущая загрузка** считается на момент документа:
  `РегистрНакопления.ЗагрузкаАттракционов.Остатки(Новый Граница(МоментВремени(), ВидГраницы.Исключая), …)`.
  Это обеспечивает идемпотентность повторного проведения (треб. 7): перед повторным
  проведением платформа удаляет прежние движения документа, и расчёт воспроизводит
  исходное решение, а не текущее состояние регистра.
- **Порог предупреждения** = `МаксимумПосетителей * ПорогПредупреждения / 100`;
  предупреждение выдаётся, если после прохода `НоваяЗагрузка >= Порог` и `ПорогПредупреждения > 0`.
- **Конкурентность (треб. 8)**: управляемая блокировка
  `Новый БлокировкаДанных` → `Добавить("РегистрНакопления.ЗагрузкаАттракционов")` →
  `УстановитьЗначение("ВидАттракциона", Вид)` → `Заблокировать()` **до** чтения остатка.
  Для «ЗавершениеПосещения» дополнительно блокируется сам документ-посещение
  (`Документ.ПосещениеАттракциона`, поле `Ссылка`) — против двойного завершения.
- **Формы** новых объектов не создаём: платформа формирует формы по умолчанию
  (список/запись регистра, форма документа). Этого достаточно для «ввода вручную» и
  просмотра лимитов. (При желании можно добавить позже.)
- **Имя тест-модуля** без префикса движка; если EDT потребует префикс расширения — использовать `ЮТ`-префикс.

### 2. Логика проведения «ПосещениеАттракциона»
В `ObjectModule.bsl`, после существующей проверки `Если Отказ Тогда Возврат; КонецЕсли;`
(существующие проверки билета не трогаем) вызвать новую процедуру:

```1c
Если НЕ ОбеспечитьЗагрузкуАттракциона(Отказ, ВидАттракционаДокумента) Тогда
    Возврат;
КонецЕсли;
```

Добавить в `#Область СлужебныеПроцедурыИФункции`:

```1c
// Проверяет допустимость прохода по лимиту вместимости, формирует движение
// загрузки аттракциона и при необходимости предупреждает о достижении порога.
//
// Параметры:
//  Отказ - Булево - признак отказа от проведения. Устанавливается в Истина,
//                   если проход превышает максимальную вместимость.
//  ВидАттракциона - СправочникСсылка.ВидыАттракционов - вид аттракциона.
//
// Возвращаемое значение:
//  Булево - Ложь, если в проведении отказано.
Функция ОбеспечитьЗагрузкуАттракциона(Отказ, ВидАттракциона)

    ЗаблокироватьЗагрузкуАттракциона(ВидАттракциона);

    Лимит = ЛимитВместимости(ВидАттракциона);
    ТекущаяЗагрузка = ТекущаяЗагрузкаАттракциона(ВидАттракциона);
    НоваяЗагрузка = ТекущаяЗагрузка + 1;

    Если Лимит.МаксимумПосетителей > 0
        И НоваяЗагрузка > Лимит.МаксимумПосетителей Тогда
        Отказ = Истина;
        Сообщение = Новый СообщениеПользователю;
        Сообщение.Текст = СтрШаблон(
            "Превышена вместимость аттракциона: %1 из %2 посетителей",
            НоваяЗагрузка, Лимит.МаксимумПосетителей);
        Сообщение.УстановитьДанные(ЭтотОбъект);
        Сообщение.Поле = "Аттракцион";
        Сообщение.Сообщить();
        Возврат Ложь;
    КонецЕсли;

    Движения.ЗагрузкаАттракционов.Записывать = Истина;
    Движение = Движения.ЗагрузкаАттракционов.ДобавитьПриход();
    Движение.Период = Дата;
    Движение.ВидАттракциона = ВидАттракциона;
    Движение.КоличествоПосетителей = 1;

    Если Лимит.МаксимумПосетителей > 0 И Лимит.ПорогПредупреждения > 0 Тогда
        Порог = Лимит.МаксимумПосетителей * Лимит.ПорогПредупреждения / 100;
        Если НоваяЗагрузка >= Порог Тогда
            Сообщение = Новый СообщениеПользователю;
            Сообщение.Текст = СтрШаблон(
                "Загрузка аттракциона достигла порога предупреждения: %1 из %2 посетителей",
                НоваяЗагрузка, Лимит.МаксимумПосетителей);
            Сообщение.УстановитьДанные(ЭтотОбъект);
            Сообщение.Поле = "Аттракцион";
            Сообщение.Сообщить();
        КонецЕсли;
    КонецЕсли;

    Возврат Истина;

КонецФункции
```

Плюс служебные `ЗаблокироватьЗагрузкуАттракциона`, `ЛимитВместимости`
(`СрезПоследних(&Дата, ВидАттракциона = &Вид)`, значения по умолчанию 0),
`ТекущаяЗагрузкаАттракциона` (остаток на момент документа, см. «Решения»).

### 3. Документ «ЗавершениеПосещения»
`ObjectModule.bsl`:

```1c
Процедура ОбработкаПроведения(Отказ, Режим)

    ЗаблокироватьПосещение(Посещение);

    ДанныеПосещения = ДанныеПосещения(Посещение);

    Если НЕ ДанныеПосещения.Проведен Тогда
        Отказ = Истина;
        Сообщение = Новый СообщениеПользователю;
        Сообщение.Текст = "Нельзя завершить непроведённое посещение.";
        Сообщение.УстановитьДанные(ЭтотОбъект);
        Сообщение.Поле = "Посещение";
        Сообщение.Сообщить();
        Возврат;
    КонецЕсли;

    Если ПосещениеУжеЗавершеноЕсть(Посещение) Тогда
        Отказ = Истина;
        Сообщение = Новый СообщениеПользователю;
        Сообщение.Текст = "Это посещение уже завершено.";
        Сообщение.УстановитьДанные(ЭтотОбъект);
        Сообщение.Поле = "Посещение";
        Сообщение.Сообщить();
        Возврат;
    КонецЕсли;

    ЗаблокироватьЗагрузкуАттракциона(ДанныеПосещения.ВидАттракциона);

    Движения.ЗагрузкаАттракционов.Записывать = Истина;
    Движение = Движения.ЗагрузкаАттракционов.ДобавитьРасход();
    Движение.Период = Дата;
    Движение.ВидАттракциона = ДанныеПосещения.ВидАттракциона;
    Движение.КоличествоПосетителей = 1;

КонецПроцедуры
```

Служебные: `ДанныеПосещения` (запрос `Проведен`, `Аттракцион.ВидАттракциона` по `Ссылка = &Посещение`);
`ПосещениеУжеЗавершеноЕсть` (проведённый `ЗавершениеПосещения` с тем же `Посещение`,
исключая `Ссылка <> &Ссылка`); `ЗаблокироватьПосещение` и `ЗаблокироватьЗагрузкуАттракциона`.
Также `ОбработкаЗаполнения`/`ПриКопировании` — `Ответственный = Пользователи.ТекущийПользователь()`.

### 4. Права роли «ОператорАттракциона»
В `Rights.rights` добавить объекты:
- `Document.ЗавершениеПосещения`: `Read, Insert, Update, Posting, UndoPosting, View,
  InteractiveInsert, Edit, InteractivePosting, InteractivePostingRegular,
  InteractiveUndoPosting, InteractiveChangeOfPosted, InputByString`
  (по образцу блока `Document.ПосещениеАттракциона`).
- `InformationRegister.ВместимостьАттракционов`: `Read, View` — **без** `Insert/Update`
  (просмотр без изменения).
- `AccumulationRegister.ЗагрузкаАттракционов`: `Read, View`.

### 5. Тесты YAXUnit (расширение)
Общий серверный модуль `Тесты_КонтрольВместимостиАттракционов`
(Сервер=Истина, ВызовСервера=Ложь, Глобальный=Ложь, Клиент=Ложь) с
экспортной `ИсполняемыеСценарии()`:

```1c
Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты
        .ДобавитьТестовыйНабор("КонтрольВместимостиАттракционов")
        .ДобавитьСерверныйТест("ТестПревышениеЛимитаЗапрещаетПроведение")
        .ДобавитьСерверныйТест("ТестБезЛимитаПроведениеРазрешено")
        .ДобавитьСерверныйТест("ТестЗавершениеПосещенияУменьшаетЗагрузку")
        .ДобавитьСерверныйТест("ТестНельзяЗавершитьНепроведенноеПосещение")
        .ДобавитьСерверныйТест("ТестНельзяЗавершитьПосещениеДважды")
        .ДобавитьСерверныйТест("ТестПовторноеПроведениеНеИскажаетЗагрузку");
КонецПроцедуры
```

Каждый тест — `.ВТранзакции()` (изоляция и автоочистка данных). Данные создаются
через `ЮТТестовыеДанные.СоздатьЭлемент`/`СоздатьДокумент` (с `РежимЗаписи = Проведение`).
Вспомогательные методы модуля:
- `СоздатьВидАттракциона()`, `СоздатьАттракцион(Вид)`;
- `СоздатьНоменклатуру(Вид)` (`ВидНоменклатуры = Enum.ВидНоменклатуры.ПосещениеАттракциона`,
  `ВидАттракциона`, `КоличествоПосещений = 1`);
- `СоздатьКлиента()`, `СоздатьФилиал()`;
- `СоздатьБилет(Клиент, Филиал, Номенклатура)` — `ПродажаБилета` с позицией, проведённый
  (даёт остаток по `АктивныеПосещения`, нужный проверкам билета);
- `СоздатьПосещение(Аттракцион, Билет, Проводить)`;
- `УстановитьЛимит(Вид, Максимум, Порог)`;
- `Загрузка(Вид)` — остаток `ЗагрузкаАттракционов`;
- `ПровестиДокумент(Ссылка)` — `Попытка … Записать(РежимЗаписиДокумента.Проведение)`, возврат Булево.

Проверки:
- **Треб. 3**: лимит `Максимум=1`; 1-е посещение проводится, загрузка = 1;
  2-е — отказ, загрузка = 1, среди `ПолучитьСообщенияПользователю(Истина)`
  есть сообщение с `Поле = "Аттракцион"`.
- **Треб. 5**: без лимита посещение проводится, загрузка = 1.
- **Треб. 6**: завершение проведённого посещения уменьшает загрузку до 0;
  завершение непроведённого — отказ; повторное завершение того же посещения — отказ.
- **Треб. 7**: повторное проведение того же `ПосещениеАттракциона` проходит, загрузка
  остаётся 1; повторное проведение `ЗавершениеПосещения` не искажает загрузку.

## Способы проверки
- После правок метаданных/кода — `GetMarkers` по каждому изменённому `.mdo`/`.bsl`:
  новых ошибок/предупреждений EDT быть не должно.
- Запустить тесты YAXUnit (обработка `ЮТЮнитТесты` в `amusementpark.YAXUNIT`) — все зелёные.
- Ручная проверка: задать лимит в `ВместимостьАттракционов`, провести посещения до
  превышения (отказ + сообщение у поля «Аттракцион»), проверить предупреждение о пороге,
  оформить «ЗавершениеПосещения» и убедиться, что загрузка уменьшилась; под ролью
  «ОператорАттракциона» — завершение доступно, изменение лимитов недоступно.

## Потенциальные сложности
- Захват пользовательских сообщений при отказе в проведении (проверка `Поле = "Аттракцион"`):
  сообщение добавляется в очередь до отказа; при недоступности в конкретном контексте
  достаточно проверять сам факт отказа и неизменность загрузки.
- EDT может требовать префикс расширения для новых объектов `amusementpark.YAXUNIT`.
- Точные обязательные реквизиты тестовых данных (`Номенклатура`, `Клиенты`, `Филиалы`)
  уточняются при реализации; программное проведение не вызывает проверку заполнения.
