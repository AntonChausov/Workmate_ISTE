# 1С:Напарник: что он действительно умеет?

Материалы к докладу на Infostart Tech Event 2026.

Это не обзор и не реклама инструмента. Это протокол исследования: какие
задачи разработчика 1С можно делегировать 1С:Напарнику уже сегодня и при
каких условиях результату можно доверять без плотного ревью. Каждый
результат в этом каталоге я проверял сам: смотрел код и метаданные в
EDT, запускал в 1С:Предприятии или прогонял тесты. Самоотчету
инструмента на слово не верил.

## Четыре поколения данных

Исследование прошло через четыре волны проверки одних и тех же задач:

1. **Оригинал** - июнь 2026, версия инструмента до крупных обновлений.
2. **Раунд 06.08.2026** - те же задачи на версии с редактированием
   метаданных, местами через затратные обходные пути.
3. **Раунд 1.0.7** (01.09.2026) - те же задачи официально заявленными
   штатными средствами. Здесь сильнее всего сдвинулась граница
   автономности по метаданным.
4. **Раунд 1.0.8** (03.10.2026) - версия, в которой 1С впервые заявила
   смену модели и длительную автономную работу по спецификации. Здесь я
   перепроверял то, что зависит от модели, а не от инструментов: тесты
   без подготовки, архитектуру, рефакторинг, форму, анализ рисков,
   скорость создания метаданных. И отдельно проверил новую функцию работы
   по спецификации.

Главное по раунду 1.0.8: тесты без подготовки выросли с 2/9 до 8/9,
центральная ошибка архитектурной задачи трех поколений ушла, в карте не
осталось ни одного 🔴 домена. Но платформенный пробел с очисткой движений
регистров устойчив, а тезис «уверенность ≠ корректность» переехал из
архитектуры в рефакторинг. Создание метаданных ускорилось (документ - с
19 до 8 минут).

Там, где задача проверялась в нескольких поколениях, в соответствующем
файле есть таблица сравнения.

## С чего начать

- Если интересна только выжимка - начните с `karta-vozmozhnostey.md`, там
  сводная таблица по всем категориям со статусами и условиями
  делегирования.
- Если интересно, как именно я проверял результаты - `metodika.md`.
- Если интересен конкретный тип задачи - соответствующий файл в
  `summary/`: там полные промпты, результаты и разбор по каждой
  подзадаче, со сравнением по поколениям, где это применимо.
- Категория `I` - три функции, впервые появившиеся в версии 1.0.7 (работа
  с приложенными изображениями, режим предварительного планирования,
  память между диалогами).
- Категория `J` - длительная автономная работа по спецификации, впервые
  заявленная в версии 1.0.8.
- Скриншоты в `screenshots/` иллюстрируют примеры, упомянутые в
  соответствующем summary-файле. Ссылки на нужные каталоги есть в конце
  каждого файла.

## Тестовый стенд

Все эксперименты проведены на демонстрационной конфигурации
`amusementpark` («парк аттракционов») - учебная база с документами
продажи и возврата билетов, учетом посещений, бонусной программой
лояльности и кадровым учетом. Конфигурация намеренно небольшая и
предметно понятная, чтобы результаты можно было проверить и
воспроизвести без специальных знаний предметной области. Для раундов
1.0.7 и 1.0.8 конфигурация возвращалась к тому же состоянию, что и перед
раундом 06.08.2026, чтобы дословно повторенные промпты сравнивались с
одинаковой стартовой точкой. Перед каждым экспериментом раунда 1.0.8 я
дополнительно очищал память Напарника.
